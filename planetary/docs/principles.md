## 1. 行星和深空为什么是两套流程

| | 深空（本仓库 `process/`、`scripts/`） | 行星（`planetary/`） |
|---|---|---|
| 目标亮度 | 极暗，信噪比是主要矛盾 | 很亮，单帧几毫秒就有足够信号 |
| 曝光 | 几十秒到几分钟一张，总共几小时 | 1–20 ms 一帧，一段视频 1–3 分钟、几千到几万帧 |
| 主要敌人 | 噪声、光污染、暗角 | **大气视宁度**（模糊 + 抖动 + 局部扭曲）、**行星自转** |
| 分辨率 | 由视宁度平均值决定（2–4″） | 尽量逼近望远镜衍射极限（0.3–0.6″） |
| 配准依据 | 星点（三角形匹配） | 行星圆面本身的纹理（相关），一帧里没有星 |
| 选帧 | 剔除少数坏帧 | **只留最好的 5–30%**，而且可以「每个局部区域各选各的」 |
| 校准 | 暗场 / 平场 / 偏置场很重要 | 一般只做平场去灰尘，暗场常省略（信号太强） |
| 后期核心 | 去梯度、拉伸、降噪 | **锐化**（小波 / 反卷积）、RGB 对齐、去自转 |

一句话：深空拼「光子数」，行星拼「抓住大气最稳定的瞬间」。

## 2. 大气湍流与幸运成像

### 2.1 Fried 参数 r0

大气折射率随温度起伏，平面波穿过大气后波前变得凹凸不平。Fried（1966）定义了相干长度 **r0**：
直径为 r0 的圆内波前相位起伏的均方根约 1 rad。r0 越大视宁度越好，可见光下典型值 5–20 cm，且 `r0 ∝ λ^(6/5)`，
所以红外波段视宁度更好（这也是很多人用 IR685 / IR742 滤镜拍木星亮度通道的原因）。

- 口径 D < r0：像主要是**整体抖动**（tip/tilt），形状接近衍射斑；
- 口径 D > r0：像碎成很多「散斑」，长曝光就是一个直径约 λ/r0 的模糊盘。

长曝光分辨率 ≈ λ/r0，与口径无关。所以 20 cm 和 35 cm 的望远镜在同一晚、同样的长曝光下可能一样糊。

### 2.2 相干时间 τ0 与等晕角 θ0

- **τ0**（相干时间）≈ 0.31·r0/v，v 为高空风速。典型几毫秒到十几毫秒 → 曝光要短于 τ0 才能「冻结」湍流，
  这就是行星单帧曝光 2–15 ms 的原因。
- **θ0**（等晕角）：天空中相距超过 θ0（几角秒）的两个点经历不同的湍流，模糊和位移不同。
  木星直径 40″+，远大于 θ0 → **同一帧里圆面不同部位清晰度不同、位移方向不同**。这是第 8 节「多点对齐」存在的根本原因。

### 2.3 幸运的概率

Fried（1978）估计了一帧「幸运」（整个口径上相位起伏 < 1 rad²）的概率：

```
P ≈ 5.6 · exp[-0.1557 · (D/r0)²]        (D/r0 ≳ 3.5)
```

D/r0 = 4 时 P ≈ 0.46；D/r0 = 7 时 P ≈ 0.03%；D/r0 = 10 时几乎为零。所以：
1. 口径越大越难整帧幸运，但**局部**幸运仍然常见 → 多点对齐 + 局部选帧；
2. 帧数要多：几千帧里挑几百帧；
3. 拍摄时间受自转限制（第 12 节），所以帧率要高 → 曝光短 → 增益高 → 单帧噪声大 → 靠叠加降噪。

### 2.4 仿真里怎么建模（`synth.py`）

| 现象 | 物理来源 | 仿真 |
|---|---|---|
| 整体抖动 | 大尺度湍流（tip/tilt） | 每帧随机平移 `--jitter` |
| 跟踪漂移 | 赤道仪误差 | 线性漂移 `--drift` |
| 局部扭曲（「沸腾」） | 等晕角小于圆面 | 平滑随机位移场 `--warp` |
| 模糊随时间变化 | r0 起伏 | 每帧高斯 σ 取对数正态分布 `--seeing` |
| 模糊随位置变化 | 非等晕 | 两种模糊按平滑随机掩膜混合 |
| 彩色错位 | 大气色散 | R/B 通道竖直方向反向平移 `--dispersion` |
| 噪声 | 光子 + 读出 | Poisson + 高斯，8/12/16 bit 量化 |

## 3. 采样：焦比、像元与 Nyquist

衍射极限下 MTF 的截止频率是 `D/λ`（周/弧度）。在焦平面上对应 `1/(λ·F)`（F 为焦比）。
Nyquist 要求像元 p ≤ λF/2，即

```
F ≥ 2p/λ          例：p = 2.9 µm，λ = 0.55 µm → F ≥ 10.5
```

实际经验值 F ≈ (3–5) × p(µm)：理论上 2p/λ ≈ 3.6×p 已经够，视宁度不完美时取 5×p 方便后期锐化，
彩色相机因为拜耳阵列每种颜色只有 1/4–1/2 采样，偏向上限。过采样只会浪费光、降低帧率；欠采样则细节永远找不回来（除非 drizzle，见第 9 节）。

## 4. 视频格式 SER 与时间戳

AVI 有编码、色彩空间、8 bit 等限制，所以 Lucam Recorder 作者 Heiko Wilkens 设计了 SER，后来 FireCapture、SharpCap、
PIPP、AS!、WinJUPOS 都支持。结构极简：

```
178 字节文件头 | 帧 0 | 帧 1 | ... | 帧 N-1 | (可选) N 个 int64 时间戳
文件头: "LUCAM-RECORDER", LuID, ColorID, LittleEndian, Width, Height, PixelDepth, FrameCount,
        Observer[40], Instrument[40], Telescope[40], DateTime(int64), DateTime_UTC(int64)
ColorID: 0=MONO 8=RGGB 9=GRBG 10=GBRG 11=BGGR 100=RGB 101=BGR
时间 = 自公元 0001-01-01 起的 100 ns 计数
```

`planetools.SerReader` 用 `np.memmap` 直接映射文件，几 GB 的视频也不占内存。注意 `LittleEndian` 标志在不同采集软件里含义相反，
实际上几乎所有文件的数据都是小端，PIPP / AS! 也都按小端读，这里同样如此。

**时间戳为什么重要**：去自转需要每段视频（甚至每一帧）的准确时间。FireCapture 的文件名 `2026-10-13-1834_5-...`
（`_5` = 0.5 分钟 = 30 秒）就是 WinJUPOS 约定的格式，`stack.py` 输出时会打印对应的文件名。

## 5. 去马赛克（Debayer）

彩色相机每个像元只测一种颜色（RGGB 等 2×2 排列）。双线性插值：

```
G 在 R/B 位置 = 上下左右 4 个 G 的平均          核 [[0,1,0],[1,4,1],[0,1,0]]/4
R 在 G 位置   = 相邻 2 个 R 的平均；R 在 B 位置 = 对角 4 个 R 的平均   核 [[1,2,1],[2,4,2],[1,2,1]]/4
```

把各色像素放到全零平面上再用这两个核卷积，就得到上面的结果（`planetools.debayer`）。
**为什么用最简单的双线性？** 行星叠加了几百帧、每帧位置随机偏移，插值误差会被平均掉；AS!4 甚至可以不 debayer，
直接对原始拜耳数据按颜色分别 drizzle（「Bayer drizzle」），彻底避免插值。PIPP 默认也是简单的双线性 / 边缘感知插值。

用反射边界补边：反射会保持拜耳阵列的奇偶性（第 −1 列映射到第 1 列，颜色相同），边缘颜色不会错。

## 6. 质量评估：怎么判断一帧「清楚」

清楚 = 高频能量多。但噪声也是高频 → 必须先轻微平滑（「Noise Robust」参数），再测高频：

| 指标 | 公式（S = 高斯平滑后的图） | 使用者 |
|---|---|---|
| 梯度能量 | mean(∂xS² + ∂yS²) / mean(I)² | AS! 的「local contrast」类指标；`frame_quality(method="gradient")` |
| 拉普拉斯方差 | var(∇²S) / mean(I)² | PIPP 的质量估计属于这一类；`method="laplace"` |
| 频谱能量 | 一定频带内 \|F\|² 之和 | 一些科研 lucky imaging 流程 |

除以 `mean(I)²` 是为了**亮度归一化**：薄云飘过时整体变暗，梯度也同比例变小，但这不代表视宁度变差。

平滑尺度的选择：σ 太小 → 噪声多的帧（反而模糊）得分高；σ 太大 → 区分不出细节。对应 AS!4 的 Noise Robust 一般取 3–8（它的单位不是像素，
大致是平滑窗口），`stack.py --sigma` 默认 1 px，噪声大（高增益、小口径）时加到 1.5–2。

**全局 vs 局部质量**：整帧打分只能反映平均情况。`stack.py` 对每个对齐点（AP）用积分图（cumsum 两次）在 O(1) 时间求框内梯度能量，
为每个 AP 单独排序选帧 —— 这就是 AS! 和 RegiStax 最大的区别。

## 7. 配准：相位相关

两张图只差平移 d：`g(x) = f(x − d)`。傅里叶平移定理：`G(k) = F(k)·e^{−2πi k·d}`。所以

```
R(k) = G(k)·F*(k) / |G(k)·F*(k)|^p   →   IFFT(R) 在 x = d 处出现尖峰
```

- p = 1：纯相位相关，峰是 δ 函数，最尖、对亮度变化不敏感，但对噪声敏感；
- p = 0：普通互相关，峰宽但稳；
- `phase_correlate(power=0.5)` 折中，行星这种低对比纹理效果最好。

**亚像素**：在峰附近用三点抛物线拟合 `δ = 0.5(c₋ − c₊)/(c₋ − 2c₀ + c₊)`，精度约 0.05 px（单元测试中 3.30 px 测得 3.25 px）。
**加窗**：先乘 Hann 窗，否则图像边缘的「周期延拓断层」会产生在 0 位移处的假峰。
**批量**：`np.fft.fft2` 对最后两维做变换，一次处理一批帧 / 一批 AP 小块，numpy 里就是一行代码。

行星和深空配准的区别：深空用星点坐标求仿射/相似变换（有旋转），行星视频几秒内**只有平移**（场旋可以忽略），所以相位相关最合适。
PIPP 的「Object detection」只求重心（整数裁剪），AS! 的「Surface」模式就是相关法，「Planet (COG)」模式是重心法。

## 8. 多点对齐（Alignment Points）

因为 θ0 < 圆面大小，每一帧都是参考图的一个**非刚性扭曲**版本。全局平移只能对齐「平均位置」，局部仍然错位几个像素，
叠加后细节被抹掉。AS!（以及 RegiStax 5/6 的多点模式）的做法：

```
1. 在参考图上铺一个 AP 网格（相邻 AP 重叠 50%），太暗的地方（天空）不放 AP
2. 每个 AP：
     a. 在 AP 框内给每帧打局部质量分，取最好的 k%      ← 局部选帧
     b. 每个入选帧在 AP 框内与参考图做相位相关 → 局部位移
     c. 按（全局 + 局部）位移从原始帧重采样一次，平均 → AP 小块
3. AP 小块用窗函数加权拼接；没有 AP 的地方用全局对齐结果补
```

**拼接权重**：周期 Hann 窗 `w(i) = sin²(π(i+½)/s)` 满足 `w(i) + w(i+s/2) = sin² + cos² = 1`，
二维可分离乘积在 50% 重叠的网格上处处和为 1（单位分解），所以拼接后不会出现方块边界，也不需要再归一化。
`stack.py` 在网格覆盖不到的边缘用 `(Σw·patch + (1−Σw)·global) / max(Σw, 1)` 平滑过渡到全局叠加结果。

**AP 大小怎么选**：太小 → 框内纹理少，相关峰不可靠（`--max-shift` 会把离谱的位移重置为 0）；太大 → 框内扭曲不一致。
经验：AP 边长约为 3–6 个分辨率元，木星 300 px 直径时 24–48 px。AS!4 的「Min Bright」对应 `--min-bright`。

**只重采样一次**：PIPP 只做整数像素裁剪，`stack.py` 先在亮度通道上算出所有位移，最后对原始彩色帧只做一次双线性插值。
每多插值一次就多一次低通。

## 9. 叠加、插值与 Drizzle

- **为什么平均**：N 帧平均噪声降 √N。行星信号强，主要噪声是读出噪声和高增益下的散粒噪声；500 帧 → 噪声降 22 倍，
  这样才经得起后面的强力锐化（锐化会把噪声放大好几倍）。
- **为什么不用 σ-clip**：深空叠加用 σ-clip 去卫星和宇宙线；行星帧数多、曝光短，几乎没有离群值，
  而且局部选帧已经把坏帧排除了。AS! 默认就是平均。
- **双线性插值的代价**：亚像素平移用双线性相当于一个随位移变化的小低通（最大在半像素处，等效模糊约 0.3–0.4 px）。
  傅里叶平移（`fourier_shift`）没有这个问题但会在边缘回卷，且对每个 AP 小块做 FFT 更慢。AS! 也是用插值。
- **Resample / Drizzle**：抖动（dither）让不同帧在像元内的落点不同，于是可以在更细的网格上重建。
  `stack.py --upscale 1.5` 是 AS! 的「Resampled」思路：直接在 1.5 倍网格上插值采样每帧再平均，
  欠采样（F 太小）时有用，过采样时只会放大图、放大噪声。真正的 Drizzle（Fruchter & Hook 2002）是把每个输入像元
  缩小成「水滴」投到输出网格上按面积加权，AS!4 的 1.5×/3× Drizzle 就是这个，这里没有实现。

## 10. 小波锐化

### 10.1 分层

把图像拆成不同尺度的细节层：

```
G₀ = I,  Gⱼ = 高斯模糊(I, sⱼ)
层 j  = Gⱼ₋₁ − Gⱼ          (Difference of Gaussians, RegiStax 的「Gaussian」小波)
残差  = Gₙ
I = 层1 + 层2 + … + 层n + 残差     （严格成立，无论 sⱼ 怎么取）
```

- **dyadic**：sⱼ = initial·2^(j−1) → 1, 2, 4, 8, 16, 32 px；
- **linear**：sⱼ = initial + (j−1)·step → 1, 2, 3, 4… px，细节层更密，适合在 1–4 px 之间精细调；
- **à trous（starlet）**：用 B3 样条核 `[1,4,6,4,1]/16` 带洞卷积，第 j 次卷积在核元素之间插 2^(j−1)−1 个零。
  这是 RegiStax「Default」小波和 PixInsight MLT 的做法（Starck & Murtagh），复用 `scripts/astrotools.starlet`。

### 10.2 锐化 = 放大细节层

```
输出 = 残差 + Σ (1 + gⱼ) · 层j
```

gⱼ = 0 原样输出。这就是**多尺度 unsharp mask**：每层的增益相当于在那个频带上把 MTF 抬高 (1+gⱼ) 倍。
大气 + 望远镜的 MTF 在高频衰减，叠加图恰好是「低对比的真实细节 + 噪声」，抬高中高频就把细节拉回来。
它不是真正的反卷积（不知道 PSF），但：
1. 只放大选定的频带，不会像逆滤波那样在 MTF 接近 0 的频率把噪声放大到无穷；
2. 每层可以单独降噪：`--denoise d` 在该层做软阈值 `sign(w)·max(|w| − t, 0)`，t = d·10·MAD-σ(层)；
3. 实时、直观，所以 RegiStax 的六个滑块成了行星后期的标准界面。

**过度锐化的代价**（`demo.py` 的实测，见 README）：增益 0.5/0.5/0.3 时与真值的误差从 10.5% 降到 6.9%；
增益加到 1/1/0.5 误差反而升到 11.7%，3/1.5/0.6 时 22%。看起来更「锐」，其实是振铃和噪声。
真值未知的实拍里，判断标准是：**不出现亮暗双边、不出现颗粒、边缘不发黑**。

### 10.3 与反卷积的关系

如果知道 PSF h，Wiener 滤波 `Ĥ*/(|Ĥ|² + 1/SNR)` 是线性最优解；小波增益可以看作对它的分段常数近似。
RL 反卷积（见 `scripts/deconvolve.py`、`docs/stacking_deconvolution_history.md`）也常用于行星，但 PSF 难测（没有星点），
需要从圆面边缘或卫星估计。AS!4 之后的新软件（如 AstroSurface、ImPPG、WinJUPOS 自带的锐化）基本也是这两类方法的组合。

## 11. 去振铃、RGB 对齐与大气色散

### 11.1 去振铃（Deringing）

行星边缘（limb）是一个强阶跃，锐化后会出现 **Gibbs 振铃**：边缘内侧一圈亮带、外侧一圈黑环。RegiStax 的 Deringing 选项、
`wavelets.py --dering` 的实现思路一样：只在边缘附近一条带里，把输出夹到原图局部邻域的 [min, max] 之内
（锐化不应该创造原图邻域里没有的极值）。远离边缘的地方不夹，因为那里正需要提高对比。

### 11.2 大气色散与 RGB 对齐

大气折射率随波长变化，蓝光比红光折射得多：天顶距 z 处的色散约 ∝ tan z，行星在 30° 高度时 400–700 nm 之间可达 2″ 以上，
远大于望远镜分辨率。表现为**上缘偏蓝、下缘偏红**（R 偏向天顶方向）。

- 拍摄时：ADC（大气色散校正器，两块可转动的楔形棱镜）抵消大部分；
- 后期：RGB 对齐 —— 把 R、B 通道分别与 G 做相位相关并亚像素平移（`wavelets.py --rgb-align`，对应 RegiStax「RGB Align」、
  AS!4「RGB Align」、WinJUPOS 也有）。仿真中设置了 ±1.0 px 色散，测得 R = −0.95 px，B = +0.96 px。

但 RGB 对齐只能修平移，修不了**每个颜色通道内部**的拖尾（宽带 R 滤镜内部也有色散），所以低空时 ADC 不可替代。

## 12. 自转与去自转（WinJUPOS）

### 12.1 自转有多快

| 行星 | 自转速率 | 周期 | 扁率 f |
|---|---|---|---|
| 木星 System I（赤道带 \|φ\| < 10°） | 877.90°/日 | 9h50m30s | 0.06487 |
| 木星 System II（其余纬度，大红斑所在） | 870.27°/日 | 9h55m40.6s | |
| 木星 System III（射电，内部） | 870.536°/日 | 9h55m29.7s | |
| 土星 System III | 810.79°/日 | 10h39m22s | 0.09796 |
| 火星 | 350.89°/日 | 24h37m23s | 0.00589 |

圆面中心的特征移动速度 `v = ω · R`（R 为赤道半径）。允许的拍摄时长 = 分辨率 / v。`derotate.py limit` 计算结果（λ = 550 nm，Rayleigh 判据）：

| 目标 | 口径 | 中心移动 | 最长视频 |
|---|---|---|---|
| 木星 45″ | 203 mm | 0.237″/分 | 172 s |
| 木星 45″ | 254 mm | 0.237″/分 | 138 s |
| 木星 45″ | 356 mm | 0.237″/分 | 98 s |
| 土星本体 18″ | 254 mm | | 370 s |
| 火星 20″ | 254 mm | | 769 s |

所以木星一段视频通常 60–120 s，超出部分要么去自转，要么分成多段视频分别叠加再去自转。

### 12.2 几何模型

WinJUPOS 把行星当成**扁球体**，正射投影（行星距离远远大于半径）到图像上：

```
体坐标：X 指向观测者所在的中央经线（赤道面内），Y 指向西（图像中「preceding」一侧），Z 指向北极
扁球面：(X² + Y²)/a² + Z²/b² = 1，  b = a(1 − f)
观测方向 d = (cos De, 0, sin De)，De = 观测者的行星中心纬度（sub-earth latitude）
图像坐标 u（向西） = Y，v（向北） = −sin De · X + cos De · Z
```

**从图像到球面**（`ray_spheroid`）：像素 (u, v) 沿视线方向的直线 `Q(t) = (−v sinDe, u, v cosDe) + t·d`
代入扁球方程是 t 的二次方程，判别式 < 0 → 不在圆面上；取较大的根（离观测者近的一面）。

**自转**：特征在 Δt 秒后经度变化 `δ = ω·Δt`。设输出时间 t₀，源图时间 tₛ，则输出像素 (u,v) 在源图中的位置是
把球面点绕 Z 轴转 `−δ`（δ = ω·(t₀ − tₛ)）后再投影回去（`rotate_view` → `project_spheroid`）：

```
Xs =  X cos δ + Y sin δ
Ys = −X sin δ + Y cos δ          Z 不变
可见性：法向量 n = (X/a², Y/a², Z/b²)，μ = n̂·d > 0 才在源图正面
```

**图像方向**（WinJUPOS 的 outline frame）：中心 (cx, cy)、赤道半径 a、北极方向角 p（从图像正上方逆时针）、是否镜像。
`derotate.py measure` 自动测：阈值分割圆面 → 面积给出 a（`a = √(面积/(π(1−f)))`）→ 二阶矩的短轴方向就是极轴
（木星扁率 6.5%，可以测出来，仿真里 25° 测得 24.5°）。180° 的多义性取最接近「北在上」的解；火星扁率太小，默认北在上。
**同一晚的所有图像共用一个半径和极轴角**（取中位数），否则 1° 的角度误差在半径 60 px 处就是 1 px 的错位。
最后用相位相关微调每张图的中心（`refine_centre`）。

**方向约定**：北在上、东在左（天空的自然方向）时，木星表面特征从左（东，following）向右（西，preceding）移动，
System II 中央经度随时间增大。用天顶镜拍的镜像图像要加 `--mirror`。**如果去自转后反而更糊，多半是方向反了**。

### 12.3 去自转的几种用法

| WinJUPOS 功能 | `derotate.py` | 用途 |
|---|---|---|
| Image derotation（Stack） | `stack` | 同一晚多段视频的叠加结果 → 去自转到平均时间 → 加权平均。等效于延长了积分时间而不糊 |
| R/G/B derotation | `rgb` | 黑白相机 + 滤镜轮：R、G、B（、L）先后拍，相隔几分钟，先去自转到同一时刻再合成彩色 |
| De-rotation of video streams | `video` | 把一段长视频的每一帧都去自转到中间时刻，再交给 AS! 叠加。可以拍 3–5 分钟甚至更长 |
| Map computation | `map` | 多张图投影到经纬度平面，拼成整颗行星的展开图 |

**加权**：每张源图的贡献权重为 `μₛ^p`（`--mu-power`，默认 1）。μ 小的地方（源图里靠近边缘、透视压缩严重）权重小，
所以输出圆面东边缘的数据主要来自较晚的图像，西边缘来自较早的图像 —— 每个位置都用「看得最正」的那张。
源图中在背面（μ ≤ 0）的点权重为 0。天空部分只平移不旋转。

**临边昏暗（limb darkening）**：同一块云在边缘比在中央暗（μ^k 律）。WinJUPOS 有专门的补偿选项；这里用 μ 加权，
在中心区域各张图的 μ 相近，影响很小，边缘区域主要取一张图，所以也基本不出现亮度台阶。

### 12.4 实测效果

仿真中渲染 18:30 和 18:40 两张无模糊图像（转了 6.04°），把 18:30 去自转到 18:40 与真值比较，
**去掉带状结构后的细节误差从 0.0070 降到 0.0008**（9 倍）。完整流程的数值见 README 的 demo 结果表。

## 13. 柱面投影图（Map）

`derotate.py map`：对地图上每个 (纬度 φ, 西经 λ)：
1. 行星面纬度 φ（planetographic，法向与赤道面夹角）→ 参数纬度 `β = atan((b/a)·tan φ)`；
2. 该图拍摄时刻的中央经度 `CM(t) = CM₀ + ω(t − t₀)`，经度差 `ℓ = CM(t) − λ`；
3. 体坐标 `(cos β cos ℓ, cos β sin ℓ, (b/a) sin β)` → `project_spheroid` → 图像坐标 → 双线性采样；
4. 多张图按 μ² 加权平均（μ < 0.15 的边缘丢弃）。

真正的 CM₀ 要由星历计算（WinJUPOS 内置），这里由用户给出（`--cm0`）；不给则经度是相对值。

## 14. 用仿真数据验证

实拍数据无法告诉你「哪种参数更接近真实」，因为没有真值。`synth.py` + `demo.py` 用已知真值评价每一步：

- **blur**：找一个 σ，使真值高斯模糊后与结果最接近 → 结果的「等效模糊」；
- **resid**：在这个 σ 下仍然剩下的误差（噪声 + 伪影）；
- **detail**：去掉沿纬度方向平滑的带状结构，只看斑点、垂珠、大红斑等「非带状」细节 —— 自转抹掉的正是这部分；
- **sharp**：与清晰真值直接比较（锐化的目标）。

这种「有真值的仿真」也是 AS!、去自转等算法作者调试时的常用手段。
