# 银河 / 星野叠加处理

固定三脚架拍摄的银河、星野照片（广角镜头 + 地景）的多帧降噪叠加。
功能对标 **Sequator**（Windows）和 **Starry Landscape Stacker**（macOS），核心算法只依赖 numpy。

| 文件 | 作用 |
|---|---|
| `stack_milkyway.py` | 主程序：天空按星点对齐叠加，地景不对齐叠加，羽化融合 |
| `exposure_calc.py` | 不拉线最长曝光：500 法则 / NPF 法则，星点漂移与天空旋转量 |

## 为什么银河叠加和深空叠加不一样

| | 深空（`process/`） | 银河星野（本目录） |
|---|---|---|
| 拍摄 | 赤道仪跟踪，长焦 | 固定三脚架，14–35 mm 广角 |
| 帧间运动 | 小幅平移（跟踪误差） | 整个星空绕天极**旋转**，每分钟 0.25° |
| 几何变形 | 视场小，相似变换足够 | 广角镜头**畸变**大，画面边缘相似变换对不齐 |
| 前景 | 没有 | 地景**不动**，不能和天空一起对齐 |
| 数据 | 黑白 FITS，线性 | 相机 RAW（彩色，线性）或 JPG/TIFF |

所以流程是：**天空和地景分开处理，最后用遮罩融合。**

```
        ┌─ 天空: 星点检测 → 匹配参考帧 → 多项式/单应变换 → 重采样 → σ-clip 叠加 ─┐
帧序列 ─┤                                                                       ├─ 羽化遮罩融合 → 输出
        └─ 地景: 不对齐，直接 σ-clip 均值 / 中值叠加（+ 去热像素）──────────────┘
```

## 用法

```bash
pip install numpy pillow rawpy        # rawpy 读 RAW；可选 tifffile 输出 16-bit 彩色 TIFF

# 1. 拍摄前：算最长曝光
python milkyway/exposure_calc.py --focal 14 --fnum 2.8 --pixel 5.9
#   NPF rule :  19.6 s  -> trail  3.4 px   (recommended)

# 2. 叠加（自动识别地平线）
python milkyway/stack_milkyway.py "shots/*.ARW" -o out/

# 3. 检查 out/sky_mask.png（白=天空）。不满意就自己画一张同尺寸遮罩：
python milkyway/stack_milkyway.py "shots/*.ARW" -o out/ --mask my_sky_mask.png

# 常用选项
--horizon 0.62          # 平直地平线（海平面、草原），位于画面高度 62% 处
--no-ground             # 纯星空，整张都按星点对齐
--model homography      # 长焦/畸变小时用单应变换；默认 poly2，畸变很大时用 poly3
--darks darks/*.ARW     # 同 ISO/快门/温度的暗场，去热像素和放大器辉光
--bin 2                 # 2×2 合并：速度快 4 倍、噪声减半，适合发手机/网络
--ground median         # 地景期间有车灯/手电时用中值
--gradient              # 去除天空的光污染梯度（多项式背景，仅作用于天空）
--sigma 3               # 剔除阈值，0 = 纯平均
```

输出：
- `milkyway_stack.tif`：RAW 输入为**线性** 16-bit 数据，可以导入 PS / Lightroom / PixInsight 继续调色；JPG 输入则保持原色调。
- `milkyway_preview.jpg`：背景中性化 + 自动 STF 拉伸后的预览图。
- `sky_mask.png`：本次使用的天空遮罩。

处理 RAW 时会在输出目录生成 float16 磁盘缓存（帧数 × 像素数 × 3 × 2 字节，例如 20 张 2400 万像素约 2.9 GB），
完成后自动删除。磁盘或内存紧张时用 `--bin 2`。

## 实现原理

### 1. 读取

RAW 用 `rawpy`（LibRaw）解码：相机白平衡、**线性 gamma（`gamma=(1,1)`）**、不自动提亮、16 位输出。
线性数据才满足「信号可加」，叠加才是物理上正确的平均。JPG 已经过 gamma 和色调曲线处理，也能叠，但暗部信息有限。

### 2. 天空遮罩

- `--mask`：用户手绘，最可靠。
- `--horizon`：平直地平线。
- 自动（默认）：**有星星的地方就是天空**。把画面分成若干竖条（条数按检测到的星数自适应），
  在每条里把星点的 y 坐标从上往下排序，遇到明显大于平均间距的空隙就认为到了地平线。
  地面上孤立的灯光因为和星空之间隔着空隙，会被排除。各条结果先剔除离群值、再平滑插值。
  这种方法偏保守（遮罩略高于真实地平线），避免地景被当作天空对齐后拖糊。

遮罩用高斯模糊羽化（默认为画面宽度的 0.6%），融合处没有硬边。

### 3. 星点检测

复用 `scripts/astrotools.detect_stars`：背景网格 → 减背景 → 局部极大 → 二阶矩测量，剔除过尖的点（热像素）。
检测前把地面区域替换成**与天空同噪声水平的随机背景**。如果替换成常数，噪声 σ 会被低估，检测阈值随之偏低。

### 4. 配准（核心）

变换定义为「参考帧像素 → 当前帧像素」，正好是反向重采样需要的方向。

1. **预测**：参考帧取中间一帧，向后、向前依次处理。相邻帧之间运动很小，用**上一帧的变换**作为初始预测。
2. **互为最近邻匹配**：把参考星按预测投到当前帧，只保留双向都是对方最近邻、且距离小于 40 → 12 → 5 px 的配对。
3. **RANSAC 单应变换**：每次随机取 4 对点，用归一化 DLT 求单应矩阵，统计内点，取内点最多的一组。
4. **最终模型迭代精修**：在内点上拟合最终模型，按残差重新选内点（< 3×MAD），重复几次。
   - `poly2`：x′、y′ 分别是 (u, v) 的二次多项式（12 个参数），可以同时吸收旋转、平移和广角镜头的径向畸变；
   - `homography`：8 个参数，适合 35 mm 以上、畸变小的镜头；
   - `poly3`：20 个参数，适合超广角、鱼眼的边缘区域。
5. **跟丢时重新捕获**：匹配失败时，对参考帧和当前帧做高通 + 4×4 降采样，用**相位相关**（FFT 互功率谱峰值）
   求平移，再重新匹配。

### 5. 重采样与叠加

- 反向双线性插值，每次处理 256 行以控制内存；画面外的区域记为 NaN，不参与平均。
- 对齐后的天空帧写入磁盘 memmap 缓存，再**逐行条带**做鲁棒 σ-clip 均值（中值 + MAD）：
  - 飞机、卫星只出现在一帧里，被剔除；
  - 热像素固定在传感器上，对齐后会落到不同的天空位置，也被剔除；
  - 噪声理论上降为 1/√N。双线性插值本身有平滑作用，所以实测的降噪倍数会略高于 √N。
- 地景用未对齐的原始帧做 σ-clip 均值或中值。热像素在地景里位置不变、无法靠剔除去掉，
  所以没给暗场时会额外去热像素（比 8 个邻居都亮 8σ 以上的像素）。

### 6. 融合与输出

`结果 = 天空叠加 × 遮罩 + 地景叠加 × (1 − 遮罩)`。
线性数据的预览：先把天空背景三通道调成中性灰，再做 PixInsight AutoSTF 式的 MTF 拉伸（背景目标 0.18）。

## 测试（合成数据）

合成 8 帧 900×600 星野：星空绕画面外的天极每帧旋转 0.15°，叠加 6% 桶形畸变；地平线为波浪形，地面上有固定灯光；
第 4 帧有一条卫星轨迹。结果：

- 8/8 帧配准成功，poly2 残差 0.4–0.6 px；
- 卫星轨迹：单帧强度 140，叠加后 0.3（已被剔除）；
- 天空噪声 0.0199 → 0.0052；
- 自动地平线中位误差约 17 px（偏保守）。真实照片的星点多得多，会更准，但仍建议检查 `sky_mask.png`。

## 拍摄建议

- 曝光按 NPF 法则（`exposure_calc.py`），ISO 1600–6400，镜头光圈全开或收半档；
- 至少 10–20 张，连续拍摄，间隔越短越好；同时拍 10 张左右暗场（盖镜头盖，参数和温度相同）；
- 地景可以在蓝调时刻单独多拍几张低 ISO 的，用 PS 合成，效果比夜间叠加更好；
- 关闭镜头防抖和机内长曝光降噪（后者会让拍摄间隔加倍）。
